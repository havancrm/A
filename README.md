# CRM ภาคสนาม

เว็บแอปสำหรับเซลล์ภาคสนาม อ่านและเขียนข้อมูลในชีต A โดยตรง โฮสต์บน Vercel

## ทำอะไรได้

- **ลูกค้า:** ค้นหาและกรอง, ดูรายละเอียด, แก้ไขข้อมูลที่กำหนดไว้ (ดู `lib/fields.js`)
- **การเยี่ยม:** บันทึกการเยี่ยมและผลการเยี่ยม
- **งานติดตาม:** เพิ่มงาน, ทำเครื่องหมายว่าเสร็จ
- **บิล:** ดูบิลของลูกค้าพร้อมยอดรวม (รวมจาก `bill_items`)
- **ผู้ดูแล (admin เท่านั้น):** สำรองชีตทั้งไฟล์, ดาวน์โหลดแท็บเป็น CSV, นำเข้า CSV

## ความปลอดภัยของข้อมูล

- ทุกการเรียก API ต้องมี Google ID token ที่ยืนยันแล้ว และอีเมลต้องอยู่ในแท็บ `ACCESS` ที่ `active = TRUE`
- คอลัมน์ `role` เป็น `admin` หรือ `sales` ผู้ใช้ `sales` ดูและแก้ลูกค้า บันทึกการเยี่ยม และงานได้ ส่วนการสำรอง ดาวน์โหลด และนำเข้าต้องเป็น `admin`
- ก่อนการเขียนครั้งแรกของวัน ระบบคัดลอกชีต A ไปยังโฟลเดอร์สำรองให้อัตโนมัติ การนำเข้าสำรองก่อนทุกครั้ง
- การแก้ลูกค้าบันทึกลงแท็บ `changes` พร้อมค่าก่อนและหลังแก้ไข
- การนำเข้า CSV เพิ่มเฉพาะแถวที่คีย์ยังไม่มี ไม่แก้แถวเดิม

## ตั้งค่าครั้งเดียว

1. **Google Cloud:** สร้าง service account แล้วเปิด Google Sheets API และ Google Drive API ดาวน์โหลดกุญแจ JSON
2. **ชีต A:** แชร์ให้อีเมลของ service account เป็น Editor
3. **โฟลเดอร์สำรอง:** สร้างโฟลเดอร์ใน Drive แชร์ให้ service account เป็น Editor จดรหัสโฟลเดอร์ (ส่วนท้ายของ URL)
   - ถ้าสร้างสำเนาไม่สำเร็จเพราะโควตา ให้ย้ายโฟลเดอร์สำรองไปไว้ใน Shared Drive
4. **OAuth client:** สร้าง OAuth client ชนิด Web application เพิ่ม origin ของ Vercel ใน Authorized JavaScript origins
5. **Vercel:** Import repo นี้ ไม่ต้องมี build step และตั้ง environment variables ดังนี้

| ชื่อ | ค่า |
|---|---|
| `GOOGLE_SERVICE_ACCOUNT_JSON` | เนื้อหาไฟล์ JSON ของ service account (เก็บเป็น secret) |
| `SHEET_ID` | `1EBE-eNNO-6gBA4QROfL7mu4WUOJlm_ID5OqktqUERPo` |
| `BACKUP_FOLDER_ID` | รหัสโฟลเดอร์สำรองใน Drive |
| `GOOGLE_CLIENT_ID` | Client ID ของ OAuth (ไม่ใช่ความลับ) |

6. **แท็บ ACCESS:** เพิ่มอีเมลผู้ใช้ พร้อม `active = TRUE` และ `role`

## คำสั่ง

- `npm install`
- `npm test` รัน unit test ของ CSV, cache, รายการช่องที่แก้ได้ และวันที่กรุงเทพ

## ข้อจำกัดที่รู้อยู่

- Vercel Hobby มีเวลาให้ฟังก์ชันทำงานประมาณ 10 วินาที การสำรองชีตทั้งไฟล์ในครั้งแรกของวันอาจใกล้เกินเวลานี้
- นำเข้า CSV ได้ไม่เกิน 2,000 แถวต่อครั้ง
- แคชอ่านข้อมูล 60 วินาที ต่อหนึ่ง instance ของฟังก์ชัน ข้อมูลที่แก้จะเห็นทันทีในเครื่องที่แก้ และเครื่องอื่นเห็นหลังแคชหมดอายุ
- ยังไม่มีการยืนยันตัวตนแบบ server-side session ทุกคำขอตรวจ ID token ใหม่
- `crm/` และไฟล์ Firebase เดิมถูกลบจากรีโพแล้ว อยู่ใน git history
